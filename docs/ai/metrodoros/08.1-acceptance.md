# Design 08.1 host integration acceptance

This branch implements the AIRI host for Metrodoros design 08.1. Its base is the fork's `develop` at `9e0d785a0`, which contains the existing local voice and avatar setup. Those prerequisite changes are outside this branch's diff.

## Ownership and data flow

The core runtime prepares the actual Conversation before any provider request or prompt projection. A private request keeps its transformed context out of durable chat history, plugin projections, and text traces. A pinned policy gates each physical Chat Completions or Responses request, including continuation and compatibility retry.

Electron main owns the credential, verified connection identity, MemoryBridge, and FileStorage. Renderers use finite Eventa commands and expiring references bound to an actor, owner generation, selection generation, and server lease. The web app uses the same owner contract with IndexedDB. Neither platform persists the connection token.

The conversation leader and speech host can be different windows. Speech requests are enumerated after the segmenter's final flush. Actual playback events determine delivery. An unavailable display surface has a bounded timeout. Notification synchronization and outbox dispatch run independently; forget acknowledgements follow confirmed generation and speech stop.

## Remaining acceptance

Real model conversation -> consolidation -> recall in a new session is not yet verified. This design P5 requirement blocks declaring 08.1 complete. The deterministic pipeline and HTTP harness results do not substitute for it.

The real Irodori/Electron audio run passed: two actual responses produced 30- and 31-character chunks of two sentences each. The first playback ended normally, the second was interrupted after 261 ms, and `stopOwner()` returned after no active AudioBufferSource remained. The intent was canceled and whole-output audio completion stayed false. [Redacted evidence](evidence/irodori-second-chunk.json). The harness uses a hidden Electron window with its own profile and real Web Audio, separate from the full application.

The actual Electron app has started with an isolated copy of non-memory settings, but a complete cross-window IPC conversation and crash/restart scenario still needs runtime acceptance. The implementation rejects an old memory-marked session when memory is turned off; a new ordinary conversation is required.


## CI repairs

The fork's optional upstream classification workflow is disabled because its Copilot workflow is not registered in this fork. Software verification jobs remain enabled. Real HTTP integration runs in the private server repository, which can check out the public AIRI source without copying a private repository credential into the fork.

The existing renderer startup tests exposed a registration wait that blocked unrelated startup work. Host registration now starts independently and is still awaited before private preparation. Unmounting the renderer revokes local provider policies and removes its facade before the next renderer installs. The three original startup tests pass without changing their assertions or timeouts.

## Windows test baseline

A full local Windows test run reported 13 failures. Eleven path, terminal, and symlink failures were reproduced in the unchanged develop baseline. The other two were five-second timeouts in glossary scanning and Chromium gestures; both passed when rerun with their original timeouts. No assertion, skip, or timeout was changed. The full repository suite remains enabled in Linux CI. Targeted memory, speech, and renderer startup tests pass on Windows.
