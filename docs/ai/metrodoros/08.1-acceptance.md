# Design 08.1 host integration acceptance

This branch implements the AIRI host for Metrodoros design 08.1. Its base is the fork's `develop` at `9e0d785a0`, which contains the existing local voice and avatar setup. Those prerequisite changes are outside this branch's diff.

## Ownership and data flow

The host restores original user text before memory ingress, retaining image descriptions and other projected parts. Host timestamps and reply decorations do not become evidence.

The core runtime prepares the actual Conversation before any provider request or prompt projection. A private request keeps its transformed context out of durable chat history, plugin projections, and text traces. A pinned policy gates each physical Chat Completions or Responses request, including continuation and compatibility retry.

Electron main owns the credential, verified connection identity, MemoryBridge, and FileStorage. Renderers use finite Eventa commands and expiring references bound to an actor, owner generation, selection generation, and server lease. The web app uses the same owner contract with IndexedDB. Neither platform persists the connection token.

The conversation leader and speech host can be different windows. Speech requests are enumerated after the segmenter's final flush. Actual playback events determine delivery. An unavailable display surface has a bounded timeout. Notification synchronization and outbox dispatch run independently; forget acknowledgements follow confirmed generation and speech stop.

The model form accepts the exact binding revision, profile UUID, and profile revision. These are supplied explicitly because the current server API has no binding-read endpoint. Leaving all three blank preserves an unmapped turn; a partial snapshot is rejected. The host does not silently adopt a later server mapping.

The HTTP harness uses a new temporary schema-6 store and a real authenticated service. It does not mock authentication, permissions, forget, or output commit. It uses distinct conversation and speech actors. Client revocation is applied only to that temporary client's SQLite row because the current API has no revoke endpoint.

## Real model and recovery acceptance

The actual Electron application passed the complete runtime scenario with an isolated profile and a fresh schema-6 store. [Redacted evidence](evidence/real-model-lifecycle.json).

The test sent two synthetic messages through AIRI: `紅茶が好きです。覚えておいてください。` and `私の好きな飲み物は何ですか？`. OpenAI gpt-4.1-mini returned HTTP 200. The extraction job succeeded, adopted the original fact as explicit, and recalled it in a new session for the same character. A second character in the same world had no copy. Correction left one current coffee preference. Forgetting removed that preference and advanced the adapter checkpoint after synchronization.

A controlled loopback proxy interrupted transport while the real server remained running. Pending events survived a forced renderer crash with their counters and identities unchanged. After main restarted, the token was required again. Reauthentication restored the same namespace and verified identity. All pending entries were acknowledged with their original sequence numbers and payload digests. The test used the public refresh command after management operations.

Model output remains subject to conservative evidence checks. A quote that includes an adjacent storage request stays a candidate. The prompt now specifies the exact sentence beside the quote field. No adoption check was relaxed.

The real Irodori/Electron audio run passed: two actual responses produced 30- and 31-character chunks of two sentences each. The first playback ended normally. The second was interrupted after 261 ms. `stopOwner()` returned with no active AudioBufferSource. The intent was canceled and whole-output audio completion stayed false. [Redacted evidence](evidence/irodori-second-chunk.json). This audio harness used a separate hidden Electron window and real Web Audio.

The implementation rejects an old memory-marked session when memory is turned off. A new ordinary conversation is required.

## CI repairs

The fork's optional upstream classification workflow is disabled because its Copilot workflow is not registered in this fork. Software verification jobs remain enabled. Real HTTP integration runs in the private server repository, which can check out the public AIRI source without copying a private repository credential into the fork.

The existing renderer startup tests exposed a registration wait that blocked unrelated startup work. Host registration now starts independently and is still awaited before private preparation. Unmounting the renderer revokes local provider policies and removes its facade before the next renderer installs. The three original startup tests pass without changing their assertions or timeouts.

A failed notification task now reconnects through the public refresh command after confirmed stop. A regression reproduces the disconnected state before this repair and confirms background synchronization resumes after it. An obsolete notification task cannot abort a replacement connection. CI runs the seven memory and settings contract files explicitly, in addition to the root suite.

Live server database probes use the server's SQLite library. This avoids separate SQLite implementations sharing POSIX locks in one process. The unchanged revocation assertion returns 401 on Linux CI.

## Windows test baseline

A full local Windows test run reported 13 failures. Eleven path, terminal, and symlink failures were reproduced in the unchanged develop baseline. The other two were five-second timeouts in glossary scanning and Chromium gestures; both passed when rerun with their original timeouts. No assertion, skip, or timeout was changed. The full repository suite remains enabled in Linux CI. Targeted memory, speech, and renderer startup tests pass on Windows.
