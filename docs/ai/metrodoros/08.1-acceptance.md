# Design 08.1 host integration acceptance

This branch implements the AIRI host for Metrodoros design 08.1. Its base is the fork's `develop` at `9e0d785a0`, which contains the existing local voice and avatar setup. Those prerequisite changes are outside this branch's diff.

## Ownership and data flow

The core runtime prepares the actual Conversation before any provider request or prompt projection. A private request keeps its transformed context out of durable chat history, plugin projections, and text traces. A pinned policy gates each physical Chat Completions or Responses request, including continuation and compatibility retry.

Electron main owns the credential, verified connection identity, MemoryBridge, and FileStorage. Renderers use finite Eventa commands and expiring references bound to an actor, owner generation, selection generation, and server lease. The web app uses the same owner contract with IndexedDB. Neither platform persists the connection token.

The conversation leader and speech host can be different windows. Speech requests are enumerated after the segmenter's final flush. Actual playback events determine delivery. An unavailable display surface has a bounded timeout. Notification synchronization and outbox dispatch run independently; forget acknowledgements follow confirmed generation and speech stop.

The HTTP harness uses a new temporary schema-6 store and a real authenticated service. It does not mock authentication, permissions, forget, or output commit. It uses distinct conversation and speech actors. Client revocation is applied only to that temporary client's SQLite row because the current API has no revoke endpoint.

## Remaining acceptance

Real model conversation -> consolidation -> recall in a new session, and real Irodori playback interrupted during its second chunk are not yet verified. These are design P5 requirements and block declaring 08.1 complete. The deterministic pipeline and HTTP harness results do not substitute for them.

The actual Electron app has started with an isolated copy of non-memory settings, but a complete cross-window IPC conversation and crash/restart scenario still needs runtime acceptance. The implementation rejects an old memory-marked session when memory is turned off; a new ordinary conversation is required.
